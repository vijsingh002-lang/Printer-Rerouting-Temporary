Temporary Printer Rerouting – Functional Specification

Version 2.0 · 2026-10-28 · matches Design v2

Printer assignment casesCase 1 no prep area · Case 2 different prep area · Case 3 same prep area fallbackView cases

Overview

Temporary Printer Rerouting lets an authorized user send all kitchen tickets from a failed printer to another compatible printer, without changing any printer configuration. It lives in the POS Terminal Devices screen under Kitchen Printer(s), and every activation needs manager authorization on the terminal.

Users

Role Can view reroutes Can request reroute or stop Can authorize
Store manager Yes Yes Yes, with their own PIN, fingerprint or manager card
Plum Support agent (remote) Yes Yes No; an on-site manager approves on the terminal
Shift lead Yes Yes No; a manager approves
Read-only staff (server, cashier) Yes No No

Principles

  • A reroute is a temporary routing override, never a printer reassignment. The original printer's IP address, prep group assignments and menu item assignments never change.
  • Scope is fixed: all prep groups served by the original printer. Receipts and other printers' tickets are never redirected.
  • A reroute applies to new tickets from the moment the store server confirms it. Tickets already waiting on the original printer can be reprinted on the destination.
  • Duration is until manually reverted. When the original printer responds again, the user is asked whether to restore the original routing.
  • The UI shows success only after the store server confirms the change. Until then the state is shown as pending.
  • Every attempt, success or failure is written to Reroute History.

Out of scope: changing printer IP or prep group setup, splitting prep groups across several destinations, scheduled or time-limited reroutes, and automatic chaining of reroutes (A → B → C). Another reroute pointing at the original printer moves only when the user chooses to move it.

Screens and functional requirements

Seven screens, all in the existing Terminal Devices visual style (dark modal, value over cyan label, pill buttons).

A. Terminal Devices

  • FR-A1 Kitchen Printer(s) lists every configured printer with name, type, IP address, status, prep group and reroute status. Status is one of Online, Offline, Fault (responds but can't print, for example a paper-feed fault) or Checking.
  • FR-A2 A search field filters by name, IP or prep group. No match shows "No printers match" with Clear search.
  • FR-A3 Each printer name shows a chevron and opens Printer details. Each row has Verify (outlined) and Reroute. Verify writes its result under the status, for example "4 ms reply", "No response" or "Paper fault". Reroute is disabled for read-only users and for printers with no prep group.
  • FR-A4 Reroute status per row:
    • Original printer: "To <destination>, Reroute Active"; "To <destination>, Destination not printing" when the destination is offline or faulted; "Status unconfirmed" after a stop that wasn't confirmed. Its Reroute button becomes Stop Rerouting (outlined red).
    • Destination printer: "From <original>, Receiving reroute", or "Receiving, not printing" when it is offline or faulted.
    • Otherwise: "None".
  • FR-A5 One banner per reroute at the top of the modal, most urgent first:
    • Red Tickets not printing when the destination is offline or faulted: Change Destination, View, Stop Rerouting.
    • Red Reroute status unconfirmed after a stop that wasn't confirmed: View, Stop Rerouting.
    • Blue <original> is responding again: Keep Reroute, View, Stop Rerouting. Keep Reroute dismisses it and the orange banner returns.
    • Orange Temporary Reroute Active: View, Stop Rerouting.
  • FR-A6 The Kitchen Printer(s) header shows "N reroutes active", or in red "N reroutes need attention" when any reroute is not printing or unconfirmed. Banners and labels stay after Verify, re-opening the modal and app restarts. Reroute History is a collapsible section below Service(s).

B. Printer details (View or printer name)

  • FR-B1 Opens a centred dialog: name, status, last seen, IP.
  • FR-B2 A printer that is offline or faulted shows a red warning explaining what can't print and whether its tickets are already rerouted.
  • FR-B3 Each reroute involving the printer shows as a card: original → destination with their status, prep groups, activated time, activated by, approved by and duration. The card title is Temporary Reroute Active, Destination not printing, or Reroute status unconfirmed, with an explanation for the last two.
  • FR-B4 The card appears on both the original printer and the destination printer.
  • FR-B5 Card actions: Stop Rerouting, Change Destination (original printer only), Open <other printer>.
  • FR-B6 Configuration (IP, model, prep group, menu items) is read-only, with a note that rerouting never edits it.

C. Reroute Printing dialog

Three steps: 1 Choose destination, 2 Review and confirm, 3 Approve and activate.

  1. Choose destination. Shows the original printer (name, IP, status), the fixed scope and duration. Connectivity is checked on open; Verify all checks again and clears the selection.
  2. Only online, compatible printers can be chosen. Each shows name, IP, status, its prep group category (same prep group, other prep group, or configured with no prep group) and a Compatible badge.
  3. The other printers sit in a collapsed Show unavailable printers (N) list, each with its reason and a neutral badge: Unavailable (offline or faulted), Incompatible, or Already rerouted. If no printer can be chosen, an empty state says what to check.
  4. Review and confirm shows original → destination and:
    • affected prep groups, scope, and "Applies to: new tickets, from the moment the store server confirms";
    • duration, with the note that the user will be asked to restore the original routing when the original printer responds again;
    • what stays unchanged (IP, prep group and menu item assignments);
    • Reprint N tickets waiting on <original>, on by default, when tickets are queued there;
    • Also move <other printer>'s reroute to <destination> when another reroute points at the original printer. It is on by default when the original printer is offline or faulted.
  5. Continue to Manager Approval opens Manager Authorization (D). Back returns to step 1; Cancel closes with nothing sent.
  6. In Change Destination mode the current destination is excluded, and it stays active until the new one is confirmed.

D. Manager Authorization

  • FR-D1 Full screen, using the existing POS Manager Authorization screen: title bar with Back and a reason line. A store manager sees "Confirm the reroute with your manager PIN."; other roles see "Printer reroute requires a Manager." A remote Plum Support agent is also told that an on-site manager has to approve on this terminal.
  • FR-D2 A detail line shows original → destination, prep groups, "until manually reverted" and who requested it.
  • FR-D3 Enter Pin with 4 masked dots, keypad 0–9, Delete, Clear and Accept. Accept is enabled at 4 digits.
  • FR-D4 Fingerprint and Manager card (labelled) approve without a PIN.
  • FR-D5 A wrong PIN clears the entry and shows the attempts left. After 3 wrong PINs, PIN entry locks for 5 minutes; the keypad and Accept are disabled, and fingerprint and manager card stay available. Each wrong PIN and the lock are written to Reroute History.
  • FR-D6 Back returns to the review step with nothing sent. On approval the request goes to the store server and the dialog shows "Waiting for the system to confirm. Printing isn't rerouted yet."
  • FR-D7 The approver is recorded: the store manager's own name for their PIN, otherwise the manager who approved.

E. Active reroute

  • FR-E1 Only after server confirmation: close the dialog, show a toast "confirmed by the store server" naming the prep groups, the destination and any reprinted tickets, then show the banner, row labels and detail cards.
  • FR-E2 Moved reroutes, reprinted tickets and the activation are each written to Reroute History.
  • FR-E3 If the destination goes offline or faults, every surface for that reroute turns red and leads with Change Destination.
  • FR-E4 When the original printer responds again, the blue recovery banner appears once and the event is logged as "Original printer responding".
  • FR-E5 Change Destination reuses dialog C and authorization D.

F. Stop Rerouting confirmation

  • FR-F1 Explains that stopping restores the original routing and shows "Printing now on" → "Returns to".
  • FR-F2 If the original printer still can't print (offline or faulted), the dialog warns that new tickets won't print and leads with Change Destination Instead; Stop Anyway is secondary. Otherwise the action is Stop Rerouting (filled red).
  • FR-F3 While waiting it shows "Rerouting is still active until then". On confirmation it closes with the toast "Original routing restored".
  • FR-F4 On failure or timeout it shows "Couldn't confirm the reroute was removed", states that rerouting may still be active, offers Try stopping again and a support reference. The banner and row change to Reroute status unconfirmed.

G. Reroute History

One row per event, newest first: time, event, outcome, user, original printer, destination printer, prep groups and note.

Destination eligibility

A printer can be chosen as a destination only if it passes every rule below; the server re-checks all rules on submit.

Rule Fails when Example Badge in the unavailable list
Not the original It is the printer being rerouted Kitchen Printer A → Kitchen Printer A Not listed
Online Connectivity check failed or timed out Patio Bar Printer, offline since 10:05 PM Unavailable
No fault It responds but can't print Cold Line Printer, paper-feed fault Unavailable
Compatible It can't print 80 mm kitchen tickets Packaging Label Printer (Zebra label) Incompatible
Not circular It is already rerouted to the original Cold Line Printer → Kitchen Printer A Already rerouted
Not itself rerouted Its own tickets are rerouted elsewhere Any printer that is an active original Already rerouted
Not current In Change Destination, it is the current destination Kitchen Printer B while A → B is active Current

All three assignment categories are allowed when they pass: same prep group (Kitchen Printer B), different prep group (Expo Printer) and no prep group (Spare Kitchen Printer).

The original printer must have at least one prep group, and only one active reroute is allowed per original printer. A printer may receive tickets from several originals.

Case 1

Printer not assigned to any prep area

Answer: Yes. The printer can be selected and used directly; it is the simplest case because no other tickets print there.

Example: Kitchen Printer A (Hot Line, Grill) is offline. Spare Kitchen Printer (192.168.20.193) is online and has no prep area.

  1. Spare Kitchen Printer appears in the destination list as "Configured, no prep group" when it is online, has no fault and can print kitchen tickets.
  2. After manager approval and server confirmation, all new Hot Line and Grill tickets print on Spare Kitchen Printer, plus any queued tickets the user chose to reprint.
  3. Spare Kitchen Printer stays unassigned in configuration. No prep area or menu category is added to it.
  4. When the reroute is stopped, it goes back to printing nothing.

Case 2

Printer assigned to a different prep area

Answer: Yes, even when its prep area has none of the same menu categories. The reroute is a local routing override on the failed printer: tickets for the original prep area are sent to the destination printer's address. The destination's prep area and menu categories are never read or changed.

Example: Kitchen Printer A (Hot Line, Grill) is offline. Expo Printer is online and assigned to Expo, which has no Hot Line or Grill categories.

  1. An order item resolves to its prep area exactly as today (for example Burger → Grill → Kitchen Printer A).
  2. Because Kitchen Printer A has an active reroute, the ticket is sent to Expo Printer instead.
  3. The ticket keeps its original prep area content and format, with a header: REROUTED – Grill (Kitchen Printer A).
  4. Expo Printer keeps printing its own Expo tickets as normal.

What does not change: Expo's menu categories and printer assignment; Kitchen Printer A's prep areas, menu categories and IP address. Grill items are not added to Expo's category list, and reports by prep area still count them as Grill.

Operational notes: tickets print at a different station, so the review step lists the affected prep groups and the ticket header names the original prep area. The destination now carries two prep areas' volume; the destination list shows each printer's current prep group so the user can judge load.

Case 3

Same prep area fallback (existing)

Answer: No change to today's behaviour. When Printer A fails, its items print automatically on the fallback Printer B in the same prep area, with no user action or manager approval.

  • Fallback is automatic and ends by itself when Printer A is back online. A temporary reroute is manual and lasts until someone stops it.
  • A manual reroute is still allowed, for example when Printer B is also offline or Printer A reports online but has a fault.
  • An active manual reroute takes priority over the fallback for as long as it runs.
  • In the destination list the fallback printer appears as "Same prep group: <prep group>".

Routing precedence

  1. The original printer has an active manual reroute → print on the reroute destination.
  2. The original printer is offline and has an online fallback → print on the fallback (existing).
  3. Otherwise → print on the original printer.

Reroutes don't chain automatically: a ticket does not follow the destination's own reroute or fallback. If the destination can't print, the reroute is flagged red everywhere and the user is led to Change Destination. When rerouting a printer that is itself receiving another reroute, the user can move that reroute in the same step.

Acceptance criteria

  • [ ] Only online, fault-free, compatible printers can be chosen; the others are listed with a reason, and the original printer is never offered.
  • [ ] Circular and already-rerouted destinations are rejected by both client and server.
  • [ ] Continue to Manager Approval always leads to Manager Authorization; nothing is sent before approval.
  • [ ] Three wrong PINs lock PIN entry for 5 minutes while fingerprint and manager card stay available; each attempt is logged.
  • [ ] Success toasts, banners and labels appear only after server confirmation.
  • [ ] New tickets for every prep group of the original print on the destination; no other tickets move. Queued tickets reprint only when the option is on.
  • [ ] Another reroute pointing at the original moves only when "Also move" is on.
  • [ ] The original printer's IP, prep groups and menu item assignments are identical before and after a reroute.
  • [ ] An active reroute is visible from the original row, the destination row, both detail dialogs and the banner, on every terminal, after restart.
  • [ ] A reroute whose destination can't print is flagged red on every surface and offers Change Destination.
  • [ ] When the original printer responds again, the user is prompted once to stop or keep the reroute.
  • [ ] Stop Rerouting needs confirmation; stopping into a printer that still can't print leads with Change Destination Instead; a failed stop keeps the reroute marked unconfirmed.
  • [ ] A concurrent change by another user is detected and never overwritten.
  • [ ] Every attempt and outcome appears in Reroute History with the fields above.
